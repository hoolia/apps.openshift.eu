# hermes 0.3.0

Released 2026-11-08.

## Changes

### A signing key for approval tokens

New values `approvalSigning.secretName` and `approvalSigning.key` (default
`approval-signing-key`). With a Secret name, container `gateway` gets that Secret key as env
`APPROVAL_SIGNING_KEY`, so a skill of the agent can sign the approval token that an MCP
server's write tool demands, at the moment the session's human approves. The dashboard,
the sidecars and the init step do not get the key.

A gateway restarted from the dashboard runs in container `dashboard` and has no key until
the pod restarts.

### Skills from a private git repository

An entry of `skills.repositories` takes `secretName`: a Secret in the release namespace in
the shape of an Argo CD repository Secret, so the same Secret can serve Argo CD and Hermes.

- SSH `url`: key `sshPrivateKey` (or `ssh-privatekey` of a `kubernetes.io/ssh-auth` Secret).
  The host key is checked against `skills.knownHosts` (default: the published keys of
  github.com) or the Secret's own `known_hosts` key.
- HTTPS `url`: key `password` (or `token`) and `username` (default `x-access-token`). A git
  credential helper reads the file; the token is never in the URL, an argument or the log.

Only init container `seed-config` mounts the Secret. The SSH key is copied with mode 0600
to a memory volume no other container mounts and removed after the clone. A missing Secret
fails that clone and keeps the skills already there.

## Upgrade

No value changes: `approvalSigning.secretName` is empty by default and no repository has a
`secretName`. The init script changes, so the pod restarts once.
