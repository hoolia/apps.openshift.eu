# hermes 0.5.0

Released 2026-11-20.

## Changes

### Public MCP servers are always listed again

The platform's public servers (the RemoteMCPServers `public-playwright` and `public-firecrawl`) are listed for every agent again, each as its own entry; `mcp.exclude` leaves one out. In 0.4.0, an agent got them only when they were ticked in `mcp.options`, and nothing ticked meant no public servers. `mcp.options` now has no effect. The key stays in the schema, so values that set it keep rendering.

### A Playwright MCP server of the team

`mcp-playwright.enabled: true` deploys the chart `mcp-playwright` as a dependency into the release namespace, as `<release>-playwright`. Its Service carries the `agentgateway.dev/mcp` port, so the platform lists it as a RemoteMCPServer and `mcp-sync` adds it next to the public servers. Every value of `mcp-playwright` applies under that key. `networkPolicy.ingressNamespaces` must admit the MCP gateway, or the gateway cannot reach the server. With `team` set, set `mcp-playwright.team` and `mcp-playwright.tenant` to the same values, so the server runs beside the agent in `<tenant>-<team>`; the render fails when they differ or when `mcp-playwright.nameSuffix` is empty. Off by default.

### Token proxy: separate MCP gateway

The token proxy reads two new variables. `MCP_UPSTREAM` sends requests under `/mcp` to that gateway instead of `UPSTREAM`, and `MCP_TOKEN_FILE`, required with it, names the projected token it sends there, so a token for `UPSTREAM` never reaches another host. Without them nothing changes.

## Upgrade

No values change. An agent that had nothing ticked gets the public servers back at its next start or `mcp-sync` pass. Values that tick `mcp.options` keep rendering; the ticks can go.
