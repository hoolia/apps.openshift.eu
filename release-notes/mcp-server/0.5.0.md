# mcp-server 0.5.0

## Changes

### Database

New values `postgres.*`: a CloudNativePG `Cluster` `<release>-postgres` in the release
namespace (1 instance, `postgres.storage.size` 1Gi on the default StorageClass,
`postgres.storage.storageClass` to pick one; requests 50m CPU and 128Mi memory, limit
512Mi). The server container gets the variable `postgres.envName` (default
`DATABASE_URL`) from the key `uri` of the Secret `<release>-postgres-app` that the
operator writes. A NetworkPolicy `<release>-postgres` admits the server on port 5432, the
instances among each other and the operator (`postgres.operatorNamespaceSelector`) on
port 8000; the server's egress policy allows the database. The chart renders no backup,
like the other charts with a CloudNativePG Cluster: a platform policy (for example one
that adds the barman-cloud plugin) or your own `ScheduledBackup` covers it.

## Upgrade

Defaults are unchanged: nothing renders unless `postgres.enabled` is set. Enabling it
on a running release creates the Cluster and restarts the server pod with the new
variable; the pod waits until the operator has written `<release>-postgres-app`.
