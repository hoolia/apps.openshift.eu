# chatwoot 0.7.0

## Changes

### Website chats become Odoo tickets

With `odoo.website.enabled` the prepare Job keeps a Website inbox (`odoo.website.inbox`,
default `Website`) for the widget on `odoo.website.url`. Its pre-chat form requires an
email address. An account webhook sends the chat events to the Odoo bridge, which acts
only on conversations of that inbox:

- The first visitor message opens a helpdesk ticket for the partner of the typed address,
  in team `odoo.website.team`. A private note links the ticket and says that the address
  is not verified.
- The bridge mails nothing to the typed address: chat tickets are created and moved without
  Odoo's stage templates, every public chat message is copied to the ticket once as an
  internal note, and a mail on the ticket shows in the chat as a private note only. Odoo
  still mails the partner when staff send a message or move the ticket to a stage with a
  template, and with automatic close or ratings on the team.
- Chatwoot allows `odoo.website.conversationsPerMinute` (5) new widget conversations per
  client address and minute. At most `odoo.website.ticketsPerEmail` (3) new chat tickets
  per address in 24 hours, and `odoo.website.ticketsPerHour` (20) in all per hour; over a
  limit the chat gets a private note instead.
- The label `odoo.website.salesLabel` (`sales`), added by staff, moves the chat to a new CRM
  lead with the transcript and moves the ticket to `odoo.website.cancelledStage`. The
  bridge requires Chatwoot's activity `<agent> added <labels>` (English and Dutch user
  interface) by a person or a Chatwoot automation, not by the chart's bridge or draft user; a label the visitor adds
  through the widget moves nothing, and staff get a private note. The AI triage reads the
  labels again just before it writes them, so a label removed meanwhile stays removed. An
  automation rule that adds the sales label on a condition the visitor controls (message
  text, contact attributes) lets the visitor move the chat: do not make one.
- Resolving the chat solves the ticket, and a solved ticket resolves the chat.

The bridge follows only the Odoo record whose `x_chatwoot_url` names the conversation: the
widget API lets a visitor change the conversation's `odoo_ref`. Off by default.

## Upgrade

No value changes. Every pod that reads the scripts ConfigMap restarts once: Chatwoot web,
Sidekiq, the login gate (with SSO), the Odoo bridge and the agent bridge. With
`odoo.website.enabled`, add the inbox to `draftAgent.inboxes` for AI drafts on chats, and
embed the widget script from the inbox settings on the website. The chart refuses a
`odoo.website.salesLabel` that is also `triage.label` or a triage category.
