# chatwoot 0.10.2

## Security fixes

### Website chats of unverified visitors open tickets on a neutral partner

The pre-chat form of the Website inbox takes any address. Before, the Odoo bridge opened the
chat ticket on the partner of that address, so a visitor could open a ticket under a real
customer's name. Now only a visitor whose identity the website verified
(`odoo.website.identity`, Chatwoot `hmac_verified`) gets the ticket on the partner of the
signed identifier. Every other chat ticket goes to one neutral partner,
`odoo.website.visitorPartner` (default `Website visitor`, ref `chatwoot-website-visitor`),
which the bridge creates once. The typed name and address stay text in the ticket
description, and the private note in the chat tells staff to confirm the visitor and then
set the ticket's customer in Odoo. A lead moved from such a chat keeps the neutral partner.

### A visitor cannot take over another conversation's agent context

The agent bot kept the A2A context id in the conversation's custom attribute
`a2a_context_id`, which a visitor can write through the widget API. A visitor who knew
another conversation's context id could continue that agent session. The bot now signs the
value for its conversation with its webhook secret and ignores any value it did not sign.

## Upgrade

- Conversations the bot holds during the upgrade start a new agent context with their next
  message: the old attribute values carry no signature.
- The Odoo user of the bridge needs to create a `res.partner` (it already does for website
  chats). The neutral partner appears with the first unverified chat.
- The bridge and agent bridge pods restart once.
