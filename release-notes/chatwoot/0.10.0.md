# chatwoot 0.10.0

## Changes

### Logged-in customers on the website chat

With `odoo.website.identity.enabled`, the Website inbox requires Chatwoot identity
validation: the site that embeds the widget signs the identifier of a logged-in customer
(their email) with the key `secrets.websiteIdentityKey` and passes it to the widget with
`setUser`. A contact identifier without a valid signature is refused. Anonymous chat and the
pre-chat form work as before.

### The bot knows who writes

Before every customer message, the Agent Bot tells its agent whether the visitor is a
customer the website verified. Any other visitor is not logged in, whatever address they
type: the agent gets no name, no email and no record of them. With
`odoo.website.identity.records` (on by default) the agent gets the verified customer's own
partner, sale orders, subscriptions and helpdesk tickets, read by the bridge from Odoo for
exactly that email. The agent itself reads no Odoo record on this path.

### The bot has its own agent

`agentBot.agentUrl` names the agent the bot asks, with the same `agent.auth`; the drafts,
the triage and the panel keep `agent.url`. Empty: the bot asks `agent.url`, as before.

### No AI draft while the bot answers

A conversation that the bot holds (status pending, in one of `agentBot.inboxes`) gets no
AI draft and no triage; both start after the handoff, through the sweep.

## Upgrade

- `odoo.website.identity.enabled` defaults to off: nothing changes.
- With it on and `secrets.type: externalSecret`, add the vault item of
  `website-identity-key` to `secrets.externalSecret.items` and give the website the same
  value. With `records`, the agent bridge needs Odoo's address in
  `networkPolicy.agentEgress`.
- The agent bridge and the prepare Job restart once.
