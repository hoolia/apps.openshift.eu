# chatwoot 0.13.1

Released 2026-11-22.

## Changes

### ConfigMap chatwoot-scripts applied server-side

Since 0.12.0, with every feature on, ConfigMap `chatwoot-scripts` is larger than the
262144 bytes that an object's annotations may hold, the `last-applied-configuration` of a
client-side apply included, so an Argo CD sync without server-side apply failed on it. The
ConfigMap now carries `argocd.argoproj.io/sync-options: ServerSideApply=true`, and Argo CD
applies it server-side whatever the Application's own sync options are.

### A lead instead of a quotation

With `agentBot.quotations.enabled`, Odoo may answer a quotation request with a lead
(`"lead": true`) when people send the quotation themselves. Before, the visitor was told
that a quotation was on its way to sign and pay. Now the visitor gets the value
`agentBot.quotations.leadMessage` (`{email}`), or with it empty the `message` of Odoo's
answer. The conversation stays with the bot unless the same answer holds `HANDOFF`. Real
quotations keep `sentMessage`.

## Upgrade

- With `agentBot`, `copilotPanel` or `draftAgent` enabled, the web, worker, gate and bridge
  pods that are installed restart once; web is briefly unavailable when the attachments
  are on a volume. Without them, no pod restarts.
- Install this version before an Odoo module that answers with leads: older versions
  announce a lead as a sent quotation.
- `agentBot.quotations.enabled` stays off by default.
- An Application that turned on `ServerSideApply=true` only because of this ConfigMap no
  longer needs it.
