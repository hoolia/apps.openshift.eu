# chatwoot 0.13.0

Released 2026-11-21.

## Changes

### An MCP server for AI agents

With `mcp.enabled`, the release runs Deployment `chatwoot-mcp`: tools for AI agents to list
and read conversations and to post private notes, never a reply to a contact. It works as
one Chatwoot agent user (`secrets.mcpToken`) and calls Chatwoot web inside the project.
kube-rbac-proxy admits a call only with a ServiceAccount token that may create
`services/proxy` on Service `chatwoot-mcp`: the ServiceAccounts in `mcp.callers`, or
`chatwoot-mcp-caller` with a long-lived token for a gateway outside the cluster
(`mcp.callerAccount.enabled`). `mcp.route.enabled` publishes `https://<host>/mcp`. The
server listens on loopback only and answers the Host headers of `mcp.route.hostname`,
`mcp.allowedHosts` and, with `mcp.callers`, its Service. It needs a chatwoot-mcp image
that reads `MCP_HOST`, `MCP_ALLOWED_HOSTS`, `MCP_ORGANIZATION`, `CHATWOOT_NOTE_INBOX_IDS`
and `CHATWOOT_API_TOKEN`. See "MCP server" in the README.

## Upgrade

- Nothing changes until you set `mcp.enabled`.
- With `mcp.enabled`, ask the platform team to bind ServiceAccount `chatwoot-mcp` to
  ClusterRole `system:auth-delegator`; without it every call is refused.
- Replacing a `chatwoot-mcp` of the `mcp-server` chart: the objects keep their names and
  this release takes them over. First remove the old release without deleting its
  objects (an Argo CD Application without a resources finalizer, or
  `argocd app delete --cascade=false`), then delete Deployment `chatwoot-mcp`, whose
  selector differs, and sync. Token Secret key `CHATWOOT_API_TOKEN` of Secret
  `chatwoot-mcp` becomes `mcp-token`.
