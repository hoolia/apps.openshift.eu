# chatwoot 0.11.0

Released 2026-11-21.

## Changes

### `/` of the host can be a chat page for customers

With `sso.public.customerPage.enabled`, `https://<hostname>/` is a full-window chat of the
Website inbox `sso.public.customerPage.inbox` instead of the staff login, with a link to
your customer portal (`portalUrl`) and a "Staff sign-in" link to `/app/login`.
`https://<hostname>/#cw=<token>` continues the conversation of that widget token, so a site
that embeds the widget can offer a bigger window. With `sso.public.customerPage.login`
(an OIDC public client with PKCE, redirect URI `https://<hostname>/`) customers log in on
the page and chat as verified customers; a customer with a session at the provider is
logged in without a click. A staff bookmark of `https://<hostname>/` then opens the
customer page: staff use `/app/login`.

### The agent sees a logged-in customer's profile and what is missing

With `odoo.website.identity.records`, the bridge's note for a logged-in customer also holds
the contact's name and phone, the company's name and VAT, and the invoice address from
Odoo, followed by `missing: <fields>`. A phone or company the website passed to `setUser`
fills a gap only. Tell the agent to ask only for the missing fields.

### The pre-chat message is a value

`odoo.website.preChatMessage` sets the Markdown message above the pre-chat form of the
Website inbox, for example a login link. Empty keeps the message set in Chatwoot.

## Upgrade

- Nothing changes until you set the new values.
- The bridge's Odoo user reads `vat`, `phone` and the address fields of `res.partner`; an
  internal user has that access.
- Chatwoot web and the agent bridge restart once.
