# chatwoot 0.3.0

## Changes

### New value `sso.deniedEmails`: addresses that never get a Chatwoot login

With `sso.enabled`, a user of the OIDC provider whose address is in `sso.deniedEmails`
gets "Access denied." from the login bridge, the same as the break-glass super admin, and
no Chatwoot user is created. Use it for shared or service accounts of the provider that
match `sso.emailDomains` and `sso.allowedGroups` but must not work in Chatwoot. The match
is on the exact address and ignores case.

## Upgrade

Nothing to do for a new value. The `chatwoot-gate` pod restarts once when the value is
set. The value refuses new logins only: an address that already has a Chatwoot user keeps
its user and its sessions. Before you deny such an address, delete its user in Chatwoot,
which also ends its sessions.
