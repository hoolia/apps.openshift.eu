# mailu 0.2.1

## Changes

### Postfix keeps its PID file in memory

Postfix writes `master.pid` and takes its lock in `/queue/pid`. That directory is now a
per-pod memory volume instead of part of the queue volume, as upstream Mailu does since
Mailu/Mailu#4161. A lock on network storage (CephFS, NFS) can no longer outlive a killed
Postfix and block the next start. The queue itself stays on the persistent volume.

The init container that patched the Postfix start script as root is removed.

## Upgrade

No values change. Postfix restarts once.
