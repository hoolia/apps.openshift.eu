# nextcloud 0.17.6

Released 2026-11-10.

## Changes

### Login button text

`oidc.loginLabel` sets the text of the single sign-on button (`{name}` is the identifier),
through user_oidc's `login_label`. The platform can set it with key `sso-login-label` in
Secret `public-nextcloud`, which wins over the value. Empty keeps "Login with <identifier>".

### Store login tokens

`oidc.storeLoginToken` (default `true`) switches on user_oidc's "Store login tokens", so apps
can call other services of the provider as the user.

### Administrators from groups and email addresses

Members of `oidc.adminGroups` and users with an address in `oidc.adminEmails` are kept in
group `admin`; the Secret keys `sso-admin-groups` and `sso-admin-emails` add to them. A user
gets the role at the first login. Only users the chart made administrator lose it again when
they no longer match; administrators made by hand stay.

### Certificate of the host owned by the chart

The chart issues the certificate of the host itself: Certificate `nextcloud-cert` writes Secret
`nextcloud-tls`, and Route `nextcloud` reads it (`spec.tls.externalCertificate`). A changed
host now gets a certificate of its own; before, cert-manager's Route controller kept serving
the certificate of the old host. A pre-install/pre-upgrade Job writes a self-signed
certificate into a missing Secret, so a new Route is admitted before the DNS of its host is
set up. The `cert-manager.io/issuer-*` Route annotations are gone from `route.annotations`.

## Upgrade

The upgrade restarts Nextcloud. Within a minute the provider is set up again once with the
new button text and token setting.

An existing Route still carries the certificate cert-manager's Route controller wrote into
it, and OpenShift refuses a Route with both that and `externalCertificate`. Remove it in the
same change, after the chart's Role `nextcloud-tls-router` exists:

```bash
oc -n <namespace> patch route nextcloud --type=json -p '[
  {"op":"remove","path":"/spec/tls/certificate"},
  {"op":"remove","path":"/spec/tls/key"},
  {"op":"add","path":"/spec/tls/externalCertificate","value":{"name":"nextcloud-tls"}}]'
```

Certificate and Secret keep the names that controller used, so the certificate is not issued
again. A platform that adds cert-manager annotations to Routes must skip Routes with
`externalCertificate`.
