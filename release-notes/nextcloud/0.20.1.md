# nextcloud 0.20.1

Unreleased.

## Changes

### Database connections

The database user `nextcloud` could hold at most 20 connections at once: mariadb-operator
gives the user of `MariaDB` `spec.username` that limit, and the chart did not change it.
A burst of more than 20 concurrent requests, such as 30 people opening a Talk call, failed
with HTTP 500 (`SQLSTATE[HY000] [1226] ... max_user_connections`).

The chart now creates the user itself with `database.maxUserConnections`, default 150, as
many requests as Apache serves in one pod. `database.maxConnections`, default 200, sets
`max_connections` of the database above it.

## Upgrade

No action. On an existing release the new limit replaces 20 at the next sync; the operator
never replaces a user that already exists. The database pod restarts once for the changed
`max_connections`, and the Nextcloud and Mailu front pods once for the `chart-version` pod
annotations.

A release installed before 0.6 whose user still points at `nextcloud-credentials` key
`mariadb-password` gets the reference to `nextcloud-mariadb` key `password`, which holds the
same password since the upgrade to 0.6.
