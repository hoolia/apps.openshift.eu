# nextcloud 0.18.0

Released 2026-11-13.

## Changes

### Push server from its own image

The push server (notify_push) runs from the image `notifyPush.image`, pinned to
`ghcr.io/nextcloud/notify_push` v1.4.2. It no longer mounts the Nextcloud volume to run the
binary of the notify_push app, and no longer has to run on the node of Nextcloud.

Before, the push server held the ReadWriteOnce volume `nextcloud-nextcloud` on its node.
When Nextcloud was evicted and scheduled on another node, the volume could not attach there
and Nextcloud stayed in `ContainerCreating` until the push server was deleted.

Keep `notifyPush.image` on the version of the notify_push app that Nextcloud installs from
the app store; `occ notify_push:self-test` reports whether they match.

### Data volume ReadWriteMany

The volume of the user files, `nextcloud-nextcloud-data`, is ReadWriteMany
(`nextcloud.persistence.nextcloudData.accessMode`). The StorageClass must support
ReadWriteMany, CephFS or NFS for example.

### Mailu 0.2.5

The bundled Mailu has a ReadWriteMany mail volume and no same-node podAffinity; see the
release notes of mailu 0.2.5.

## Upgrade

A volume claim cannot change its access mode, so Argo CD fails on the existing claims
`nextcloud-nextcloud-data` and `mailu-storage` until they are ReadWriteMany. Migrate both
first, as described in the Upgrade section of mailu 0.2.5, for each claim. Nextcloud and
Mailu are down while their claims are recreated, a few minutes. No data is copied.

The upgrade restarts the push server; clients reconnect within a minute.
