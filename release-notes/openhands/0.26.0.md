# openhands 0.26.0

Released 2026-11-20.

## Changes

### Public MCP servers are always listed again

The platform's public servers (the RemoteMCPServers `public-playwright` and `public-firecrawl`) are listed for every agent again, each as its own entry that the user can switch off. In 0.25.0 and 0.25.1, an agent got them only when they were ticked in `mcp.options`, and nothing ticked meant no public servers. `mcp.options` now has no effect. The key stays in the schema, so values that set it keep rendering.

### A Playwright MCP server of the team

`mcp-playwright.enabled: true` deploys the chart `mcp-playwright` as a dependency into the release namespace, as `<release>-playwright`. Its Service carries the `agentgateway.dev/mcp` port, so the platform lists it as a RemoteMCPServer and `mcp-sync` adds it next to the public servers. Every value of `mcp-playwright` applies under that key. `networkPolicy.ingressNamespaces` must admit the MCP gateway, or the gateway cannot reach the server. Off by default.

### Models and MCP servers from different gateways

New `gateway.mcpUpstream` and `gateway.mcpAudience`. When `gateway.mcpUpstream` is set and differs from `gateway.upstream`, the token proxy sends `/mcp` there with a ServiceAccount token for that audience (default: its host), and `mcp-sync` routes the RemoteMCPServers on that gateway through the token proxy. Models stay on `gateway.upstream`. A team whose models come from its own gateway, for example its own Bifrost, then reaches the platform's MCP servers like any other agent. Before, the token proxy sent `/mcp` to `gateway.upstream`, so such an agent asked its own gateway for MCP servers it does not serve.

## Upgrade

No values change. An agent that had nothing ticked gets the public servers back at its next start or `mcp-sync` pass. Values that tick `mcp.options` keep rendering; the ticks can go.

A team with its own model gateway sets `gateway.mcpUpstream` to the platform gateway, for example `https://api.grn.cloud`.
