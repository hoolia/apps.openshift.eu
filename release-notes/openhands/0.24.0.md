# openhands 0.24.0

Released 2026-11-19.

## Changes

### MCP OAuth logins stay fresh without a conversation

The agent-server refreshed an MCP OAuth access token only when a conversation called that
server after the token had expired. A login nobody used for a while died with its refresh
token: providers expire an idle refresh token, and Claude Code and Codex, which get only the
stored access token over ACP, never refresh it.

A thread of the agent-server (module `mcp_oauth_refresh`) now refreshes every OAuth login of
the settings that has a refresh token, every five minutes when it is due: when its access
token has less than 15 minutes or a quarter of its lifetime left, and at least once a day. It
stores the new tokens through the same settings token store as a conversation. It never
starts an interactive login and never removes a stored login: a failed refresh is logged in
the log of `agent-canvas` (`mcp_oauth_refresh: <server>: refresh failed, ...`) and retried
after an hour.

A conversation whose access token expired now reads the stored tokens again before it
refreshes, so it uses the token the thread stored and does not send a refresh token that a
provider with rotating refresh tokens (Atlassian) has already revoked.

## Upgrade

No values change. The agent image is rebuilt once under the tag `1.38.0-0.24.0` and the agent
pod restarts. A login whose refresh token already expired still needs **Reauthorize** under
**Settings > MCP** once.
