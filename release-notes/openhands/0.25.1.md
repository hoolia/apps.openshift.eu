# openhands 0.25.1

Released 2026-11-20.

## Changes

### MCP server timeouts are in seconds

The UI takes an MCP server's timeout in seconds, at most 3600. The agent-server hands the value to fastmcp 4, which reads it in milliseconds. The chart wrote 60000 so tool calls got 60 s, and the UI then refused to save any server the chart writes, with "Timeout cannot exceed 3600 seconds (1 hour)", also on Reauthorize. A server added in the UI with timeout 60 timed every tool call out after 60 ms.

The new agent-server module `mcp_timeout_seconds` converts the timeout from seconds to milliseconds where the SDK builds the fastmcp config, for conversations and for the MCP test of the UI. `mcp-sync`, the `mcpServers` seed and the kubernetes MCP server write 60 seconds. A stored value above 3600 is read as milliseconds, so servers written by an earlier chart keep working until `mcp-sync` or the seed rewrites them.

## Upgrade

No values change. `mcpServers[].timeout` was already in seconds.
