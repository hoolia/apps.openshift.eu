# vaultwarden 0.1.4

Released 2026-11-08.

## Changes

### Single sign-on, on by default

New value `sso.enabled`, default `true`. Vaultwarden logs in at the OpenID Connect client
of Secret `public-vaultwarden` (`sso.secretName`) when the platform makes one, and does
nothing while the Secret is not there. The platform answers only a Deployment with its
label (`deploymentLabels`), so an install without the label behaves as before.

The Secret is an optional volume. The start script `sso.sh` reads it every `sso.interval`
seconds (default 30) and restarts Vaultwarden in its container when the client appears,
changes or goes; the pod keeps running.

A user the issuer signs in gets an account on the same terms as a password signup
(`SSO_SIGNUPS_ALLOWED` follows `signups.allowed`). The master password still unlocks
the vault, and the email and password login stays.

### Labels on the Deployment

`deploymentLabels` puts extra labels on the Deployment only, not on its pods.

## Upgrade

Nothing to do; the pod restarts once. To keep single sign-on off where the platform
labels the Deployment, set `sso.enabled: false`. A release that sets `SSO_*` in
`extraEnv` keeps those values while the Secret is not there; with the Secret, its client
wins over `SSO_ENABLED`, `SSO_AUTHORITY`, `SSO_CLIENT_ID` and `SSO_CLIENT_SECRET`.
